CvT-24: Convolutional Vision Transformer from First Principles

A modular PyTorch implementation of the Convolutional Vision Transformer without high-level library abstractions, exploring shift-invariance injection via depthwise separable convolutional token projections.

Code: GitHub Repository ↗ Framework: Pure PyTorch Attention: Custom Depthwise Projections Structure: Hierarchical Stages

§ 1. Problem Formulation

Vanilla Vision Transformers (ViT) partition images into non-overlapping patches and linearly project them into 1D token embeddings. While this scales effectively given hundreds of millions of pre-training images, it discards essential 2D spatial locality and translation equivariance, requiring quadratic compute overhead and explicit positional encodings that break under variable image resolutions.

§ 2. Motivation & First-Principles Implementation

Convolutional Vision Transformers (CvT) inject the inductive biases of CNNs (shift-invariance and local feature hierarchies) directly into the tokenization and self-attention projections. Rather than importing wrapper libraries (such as Timm or Hugging Face), implementing CvT-24 from mathematical specifications in pure PyTorch illuminates the exact tensor mechanics governing depthwise separable projections, overlapping patch embeddings, and resolution-agnostic positional representations.

§ 3. Architectural Design & Forward Flow

CvT-24 replaces standard linear patch projections with depthwise separable convolutions in both token generation and query/key/value projection within transformer blocks across 3 hierarchical stages.

Hierarchical Multi-Stage Pipeline: Input [3×224×224] ➔ Stage 1: Conv Token Projection (stride 4, dim 64) ➔ 2 Transformer Blocks ➔ Stage 2: Conv Token Projection (stride 2, dim 192) ➔ 2 Transformer Blocks ➔ Stage 3: Conv Token Projection (stride 2, dim 384) ➔ 20 Transformer Blocks ➔ Global Average Pooling ➔ Classifier

Convolutional Token Projection: Implemented via 2D depthwise convolution with stride and kernel overlap, naturally handling spatial downsampling and removing the requirement for learned 1D position embeddings.

§ 4. Experimental Setup

Benchmarks: Evaluated on CIFAR-100 and ImageNet-100 subsets to verify parameter scaling, training stability, and mathematical equivalence with published reference implementations.

Hardware & Framework: PyTorch 2.1 with CUDA 12.1 on 1× NVIDIA RTX 3080 GPU (10GB VRAM), utilizing native Automatic Mixed Precision (AMP).

Hyperparameters: AdamW optimizer, initial lr = 5e-4, cosine learning rate decay, weight decay = 0.05, 100 training epochs, batch size = 64.

§ 5. Results & Baseline Comparisons

The from-scratch implementation constructs Microsoft's CvT-24 architecture in pure PyTorch, verifying depthwise separable token projections and multi-stage hierarchical feature representations without library wrappers.

§ 7. Scientific Limitations & Threats to Validity

Scientific Limitations 1. Memory Access Latency: Depthwise separable convolution layers exhibit lower arithmetic intensity than standard matrix multiplications, resulting in slight memory bandwidth bottlenecks on consumer GPUs without custom fused kernels.
2. Evaluation Scope: Validated on medium-scale benchmarks; requires ImageNet-1k full scale pre-training checkpoints for definitive top-1 convergence claims.

Future Work: Implementing custom Triton GPU kernels to fuse convolutional token projections with self-attention QKV projections to maximize tensor-core utilization.
